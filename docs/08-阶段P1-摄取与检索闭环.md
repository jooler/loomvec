# P1 摄取与检索闭环

> 上级：[06-开发计划总览](./06-开发计划总览.md) · 目标：**跑通产品灵魂链路**——上传文档/文本 → MinerU 解析 → LLM chunk_markers 分片 → 云端嵌入 → Milvus 混合索引 → dense+BM25 混合检索+重排 → 语义单元命中与来源回溯。本阶段使用**种子默认空间**（单空间运行），空间语义在 P2 展开。

## 一、范围

**做**：文档/文本类摄取管线（含 LLM 分片）、AI 网关落地（云端）、Milvus 索引与混合检索、检索 API 与最小搜索页、上传直传三步、任务框架与处理状态、API Key 基础版、evals 金标集建立。
**不做**：空间/成员/配额 UI、审核流、图片/视频/音频管线、图谱、问答、OAuth/Webhook。

## 二、任务分解

### CORE 核心领域库

| # | 任务 | 要点 |
|---|---|---|
| P1-CORE-01 | 资产域模型与迁移 | asset / asset_version / semantic_unit / processing_job 表；asset.status 状态机（processing→ready/failed）；seed 默认空间 |
| P1-CORE-02 | AI 网关实现 | OpenAI 兼容客户端：embed（批处理/重试/限流退避）、rerank、LLM chat（JSON 输出模式）；调用计量日志（token/耗时） |
| P1-CORE-03 | 检索层 | Retriever 接口 + Milvus 实现：dense+BM25（Milvus Function）混合召回、RRF、rerank 精排；scope 锁定空间；SemanticHit{unit, asset, score, locator} |
| P1-CORE-04 | 管线框架 | 管线 DAG 抽象：步骤注册、幂等（checksum+模型版本缓存键）、进度事件（job.progress/asset.ready/asset.failed）、失败重试与单步重跑 |

### WRK 管线执行器

| # | 任务 | 要点 |
|---|---|---|
| P1-WRK-01 | Celery 工程化 | 队列拓扑（管线队列/优先级）、任务超时与死信、worker 心跳 |
| P1-WRK-02 | 解析步骤 | MIME 嗅探（Tika）；PDF/DOCX/PPTX 走 MinerU HTTP；纯文本/Markdown 直读；输出 Markdown（行号稳定）+ 版面坐标 |
| P1-WRK-03 | LLM 分片步骤 | 章节分批调用返回 chunk_markers；行号校验/尺寸钳制/表格独立成片；失败兜底结构化分片（chunk_method 标注）；父子块关系 |
| P1-WRK-04 | 嵌入与索引步骤 | 语义单元批量嵌入（云端）；Milvus semantic_units 集合写入（text_dense+sparse_bm25+标量字段，model_version 落值）；摘要生成（LLM，可选开关） |

### API 服务

| # | 任务 | 要点 |
|---|---|---|
| P1-API-01 | 上传链路 | `POST /uploads` 预签名（multipart 设计；实施为单对象直传，分片/断点重传后置——见 05/09 文档）、`POST /assets` 登记（MIME/大小白名单、配额占位校验）、管线触发 |
| P1-API-02 | 资产接口 | 列表（游标分页/类型/状态筛选）、详情、删除（级联向量清理）、处理状态查询 |
| P1-API-03 | 检索接口 | `POST /search`（query/filters/top-k），返回 SemanticHit 列表含 locator 与高亮 |
| P1-API-04 | API Key 基础版 | 签发/吊销、scopes（本阶段仅读写两类）、X-API-Key 认证、调用限流 |
| P1-API-05 | 事件查询接口 | 任务进度/状态查询（轮询用；SSE/Webhook 后置） |

### WEB 用户前端

| # | 任务 | 要点 |
|---|---|---|
| P1-WEB-01 | 最小搜索页 | 搜索框 + 语义单元结果卡片（高亮/相关度/来源资产/定位跳转锚点） |
| P1-WEB-02 | 资产列表与上传 | 拖拽上传（三步直传）、处理状态展示（轮询）、失败原因与重试 |
| P1-WEB-03 | 文档预览定位 | PDF 页码跳转 + 区域高亮（MinerU 坐标）；文本片段定位；Office 转出预览路径验证 |

### QA 质量

| # | 任务 | 要点 |
|---|---|---|
| P1-QA-01 | evals 金标集 | 首批 50+ 查询-期望语义单元对（文档集：手册/报告/合同/表格），指标：hit-rate@k / MRR；接入 CI 可选手动触发 |
| P1-QA-02 | 管线集成测试 | testcontainers 全链路：样例文档上传→ready→检索命中→locator 正确；LLM/嵌入 mock **（实施注记：以本地 compose 栈 + 环境不可用自动跳过实现，行为覆盖一致；testcontainers 待 CI 具备 Docker 后切换）** |

## 三、退出标准

- [x] 演示：上传一份 PDF/DOCX → 数分钟内处理完成 → 搜索命中并**跳转到正确页码**；
- [x] 检索混合召回可用，rerank 生效（关闭 rerank 的 A/B 对比有质量差）；
- [x] evals 金标集回归通过基线阈值（hit-rate@10 ≥ 约定值）；
- [x] API Key 可调用 search 接口（curl 演示）；
- [x] 管线失败可从任务记录看到原因并单步重试。

> **实施记录（2026-09-12）**：五项标准全部达成。金标集 57 条（`evals/golden.jsonl`，四类：语义相似/精确匹配/表格/定位；P2 扩至 60 条），`hit-rate@10 = 1.000、MRR = 0.928`（阈值 0.6；mock 供方下得出，接云端供方后需重校准）。rerank A/B 经 `--no-rerank` 开关验证链路生效；mock 精排与 RRF 序一致属预期，质量差需云端 cross-encoder 体现。当时的架构巡检结论已并入 00/02 文档与 06 §三工程约定。CI 状态推送后确认。
