# LoomVec 运维前端（apps/admin）初步设计

> 状态：已随 P4 落地（2026-09） · [00-项目核心文档](./00-项目核心文档.md) 的设计附件 · 范围：`apps/admin` SPA

## 一、定位与边界

- **服务对象**：平台运营方（经营方）的运维与运营人员。
- **核心职责**：应用状态观测、全局配置管理、租户/用户/权限治理、空间与内容治理、管线运营、开放平台（API Key/OAuth/Webhook）管理、审计。
- **边界（不做）**：不接管终端用户日常操作（上传/编辑自己的空间走用户前端）；不含业务 API 逻辑（一切经管理 API）；深度性能观测外链 Grafana，本端呈现聚合视图与关键指标；不做以用户视角的权限诊断/模拟登录。

## 二、技术方案

| 项 | 决策 |
|---|---|
| 框架 | React 18 + TypeScript + Vite，Tailwind CSS v4 + shadcn/ui（Sidebar 侧边栏布局） |
| 服务端状态 | TanStack Query（缓存/失效/轮询），本地 UI 状态用组件内 state，不引入全局 store |
| 路由 | React Router，路由级权限守卫 |
| API | 一律经 `packages/sdk-ts`（OpenAPI 生成）调用 `/api/v1/admin/*` 域，禁止手写请求 |
| 认证 | 复用平台 JWT + OIDC 登录；无独立账号体系 |
| 部署 | 静态资源，与用户前端同构（Nginx / 对象存储托管） |

## 三、平台角色与权限（运营端自身）

平台角色与租户内 RBAC 相互独立，仅控制运营端：

| 角色 | 权限 |
|---|---|
| `super_admin` | 全部功能，含系统配置与平台角色分配 |
| `operator` | 租户/空间/内容/管线/开放平台的日常运营，改不了系统配置 |
| `auditor` | 全局只读 + 审计导出 |

- 双闸控制：路由守卫（菜单/页面不可达）+ 按钮级权限指令（动作不可见/禁用）。
- **所有写操作进审计**：操作者、对象、变更前后值、必填理由；危险操作二次确认。

## 五、模块设计

### 5.1 总览（/overview）
- **健康卡片**：api / worker / PostgreSQL(+AGE) / Milvus / RustFS / Redis / MinerU 七个组件的存活与版本，异常红色告警；
- **管线态势**：当前队列深度、24h 吞吐、失败率、各阶段（解析/分片/抽取/嵌入/索引）耗时 P50/P95；
- **平台规模**：租户/空间/资产/语义单元/实体数量、存储用量、向量规模；
- **待办聚合**：失败待重试任务数、待审资产数、实体合并待审数——点击直达对应页面。

### 5.2 租户管理（/tenants）
- 列表：名称、状态、配额使用率（存储/文件数）、空间数、用户数；创建/停用租户；
- 详情：配额调整、用量报表、下属空间与用户跳转；**OIDC 域/组织绑定**（该域登录的用户自动归属本租户，域内首个用户由租户管理员分配角色）；
- 停用语义：冻结登录与 API 访问，数据保留；清理为独立危险操作（二次确认 + 理由）。

### 5.3 用户与权限（/users、/roles）
- 用户列表：所属租户、状态、来源（本地/OIDC）、最近活跃；禁用/启用、角色分配；
- 角色管理：平台角色分配（三角色）；租户内角色模板（owner/editor/viewer）的展示与说明（模板本身由产品预置，不开放自定义）。

### 5.4 空间治理（/spaces）
- 全量空间列表（**含个人空间**）：类型、所属租户、owner、成员数、存储/文件数、先审后见开关状态、状态（正常/封禁）；
- 空间详情：成员列表、配额、嵌入模型与分块预设、图谱/索引状态；
- 治理动作：封禁/解封、owner 转移、内容清空（危险操作）、配额单独调整。

### 5.5 内容审核（/reviews、/content）
- 审核队列：开启"先审后见"的共享空间的待审资产，批量通过/驳回（驳回必填理由，通知 owner）；
- chunk 质量复核：按资产查看语义单元切片结果（chunk_markers 来源标注：LLM 分片 / 结构化兜底），预览原文定位；
- 下架：资产级 / 语义单元级（连带向量与图谱溯源清理）。

### 5.6 管线监控（/pipeline）
- 任务看板：按状态（排队/进行中/成功/失败）、管线阶段、资产类型筛选；失败原因聚合 Top N；
- 任务详情：输入资产、各阶段耗时分解、错误堆栈、重试次数；
- 操作：单任务重试、按资产/空间批量重跑（任务化，进度可见）。

### 5.7 模型与检索管理（/models、/retrieval、/evals）
- 嵌入模型白名单：空间可选择的模型/分块预设集合（运营配置，用户只能从中选）；
- 重嵌入：模型切换后的全量/增量重嵌入任务，进度与断点续跑状态；**过渡策略**——向量携带 model_version，重嵌入期间检索按空间旧版本继续服务，完成后原子切换空间模型版本；
- 索引与图谱：Milvus 集合状态、AGE 图谱重建、实体合并审核（merge_log 审阅/回滚）、社区重建触发；
- 评测报告（/evals）：检索评测集回归结果趋势（语义相似/精确匹配/多跳关系/全局总结四类指标）。

### 5.8 开放平台（/open/*）
- API Key：签发（scopes 精确到权限点）、限流、过期、用量统计、吊销；
- OAuth 应用：redirect_uris、scopes 管理、启用/停用；
- Webhook：事件订阅管理、投递日志、失败重放。

### 5.9 系统配置（/settings/*）
- AI 供方：向量化/rerank/VLM/LLM 的服务地址、密钥、模型名（云端直连；内网化时仅改此处配置）、调用超时与并发上限；
- 检索参数：三路召回开关、RRF 参数、重排模型与 top-k、图谱跳数；
- 上传策略：类型/大小白名单、配额默认值；
- SSO/OIDC：IdP 端点、客户端凭据、属性映射；
- 扩展插件：`extensions/` manifest 列表、加载/启停、配置项编辑。

### 5.10 审计日志（/audit）
全量写操作 + 登录事件；按操作者/对象类型/时间/租户筛选；导出（auditor 可用）。

### 5.11 系统状态（/system）
组件健康详情（含 MinerU 解析服务版本与模型信息）、worker 在线副本、队列深度、任务执行器心跳、平台版本与构建号、备份恢复状态。

### 5.12 系统初始化
- 首个 super_admin 由部署引导创建（一次性引导令牌或环境变量注入），首次登录强制完善凭据；
- 初始化向导：AI 供方端点连通性检查 → OIDC/IdP 配置 → 上传策略与默认配额 → 存储组件健康确认，完成后进入总览。

## 六、关键交互约定

1. 危险操作（封禁、清空、下架、重建）：二次确认 + 必填理由 → 审计留痕；
2. 批量与长任务（批量重跑、重嵌入、图谱重建）：一律任务化进入管线任务体系，页面展示进度，不阻塞操作者；
3. 列表页统一提供租户/空间/时间筛选器与列自定义；
4. 配置修改即时生效项与需重启生效项明确标注。

## 七、管理 API 域约定

- 独立路由域 `/api/v1/admin/*`：独立 scopes（`admin:*`），仅平台角色可访问，复用平台限流与审计中间件；
- 应用状态数据来源：各组件健康端点 + `processing_job` 聚合 + 队列深度 + 存储统计，由管理 API 聚合输出；Prometheus/Grafana 承担细粒度指标，admin 页面外链跳转；
- 前端不直连任何基础设施（不直查 PG/Milvus/Redis），一切经管理 API。
