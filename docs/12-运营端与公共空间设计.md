# LoomVec 运营端与公共空间（apps/ops + P5 后端）设计

> 状态：**已落地（2026-09-14，P5）** · [00-项目核心文档](./00-项目核心文档.md) 的设计附件 · 范围：`apps/ops` SPA、`/api/v1/ops/*` 与 `/api/v1/public-spaces` API 域、迁移 0007
> 本文是该能力的事实文档（SSOT）：三端分工、数据模型、授权语义、API 契约、页面 IA 均以此为准。

## 一、背景与三端分工

平台此前有管理端（apps/admin，系统运维）与用户端（apps/web）两个前端。企业需要把"公共知识库"的**内容运营**从**系统运维**中拆出：

| 端 | 应用 | 职责 | 角色 |
|---|---|---|---|
| 管理端（运维端） | `apps/admin` | 系统运维事务：租户/用户/平台角色、空间治理（封禁/配额/清空）、审核复核、管线、开放平台、系统配置、审计。**维持现状，本阶段未改动** | super_admin / operator / auditor |
| **运营端（新增）** | `apps/ops` | **纯知识库维护业务**：创建并维护多个公共空间（内容上传/审核/图谱），决定空间对哪些**用户分组**公开。**不含**用户端的对话、检索、通知功能 | operator / super_admin（复用平台角色，auditor 不进入） |
| 用户端 | `apps/web` | 个人/共享空间协作 + **公共空间只读浏览** + **链接开关**（问答检索源） | 空间角色 owner/editor/viewer；公共空间对普通用户为虚拟 viewer（无成员行） |

命名约定：`apps/admin` 沿用"运维端"称呼（系统运维）；`apps/ops` 为"运营端"（内容运营）。

## 二、核心语义

1. **公共空间（space_type=public）**：由运营端创建维护的空间类型（`SpaceType.PUBLIC`，迁移 0007 追加枚举值）。用户端**禁止**创建（`POST /spaces` 携带 `space_type=public` → 422）。
2. **用户分组**：全新的授权单元（`user_group` / `user_group_member`），与空间成员角色（space_member）**完全解耦**。仅运营端提供分组管理入口（管理端/用户端均无）。
3. **分组可见性**：`space_group_visibility` 行存在即"该空间对该分组可见"。运营端可见性页签**勾选分组 = 公开**；空集合 = 不对任何人公开。PUT 全量替换勾选集合。
4. **浏览与链接分离**：
   - **可见即可只读浏览**：出现在 `GET /public-spaces` 列表中的空间，用户可进入 `/s/:id` 浏览资产/检索/图谱（`require_space` 对分组可见的公共空间授予**虚拟 viewer**，不写 `space_member`）；写操作（上传/改设置/成员管理等）仍要求真实 editor/owner 成员 → 403。
   - **链接（space_link）**：仅控制是否作为**问答检索源**（幂等 `PUT /public-spaces/{space_id}/link`）。与浏览解耦——未链接也可浏览；已链接才可在对话页「召回空间」中选中。
   - 聚合检索（POST /search 缺省）仍以成员空间为界，公共空间**不进入**通用检索结果；
   - 公共空间唯一进入问答召回的通道是**会话 `scope_space_ids` 显式选中**（见 §四授权语义）。
5. **失效即时代**：分组被移出可见集合 / 用户被移出分组 / 空间被封禁后，既有链接行保留但检索即时失效，且**浏览闸门同步关闭**——`authz.linked_public_space_ids` / `is_public_space_visible` 每次查询即时求交（与"被移出成员即失权"同语义），不做后台清理。

## 三、数据模型（迁移 0007）

| 表 | 说明 |
|---|---|
| `user_group` | 用户分组：tenant_id + name（租户内唯一 `uq_user_group_tenant_name`）+ description；软删 |
| `user_group_member` | 分组-用户关联（CASCADE，`uq_user_group_member_pair`），一用户可属多分组 |
| `space_group_visibility` | 空间-分组可见勾选（CASCADE，`uq_space_group_visibility_pair`） |
| `space_link` | 用户-公共空间链接（CASCADE，`uq_space_link_pair`） |

- 枚举 `space_type` 追加 `'public'`（`ALTER TYPE ... ADD VALUE IF NOT EXISTS`；降级不回收该值，重建类型成本高且保留无副作用）。
- **Seed**：演示分组「公共访问」（alice/bob/carol 三种子用户），未挂任何空间。
- 模型落位：`core/db/models/identity.py`（分组）/ `core/db/models/space.py`（可见性与链接）；`SpaceType.PUBLIC` 同文件。
- ⚠️ 迁移注意：0005 为 AGE 初始化设置过**会话级** `search_path = ag_catalog, ...`，其后迁移的非限定 `CREATE TABLE` 会落入 `ag_catalog` schema——0007 在 upgrade/downgrade 开头先复位 `SET search_path = "$user", public`（已实测升级→降级→再升级闭环）。

## 四、授权语义（core/authz.py 单点）

```
成员空间（现状）    visible_space_ids(user)          = space_member 行
分组可见公共空间    visible_public_spaces(user)      = space(public,未删,未封禁) ⋈ space_group_visibility ⋈ 我的分组
可检索公共空间      linked_public_space_ids(user)    = linked_public = 可见公共空间 ∩ 我已链接
问答可检索全集      = visible_space_ids ∪ linked_public_space_ids
只读浏览资格        = 成员空间 ∪ 分组可见公共空间（后者经 require_space_role 虚拟 viewer）
```

- 空间闸门（`require_space_role`）：真实成员按角色；非成员若公共空间对其分组可见且 `min_role=viewer`，返回 `SpaceAccess(effective_role=VIEWER)`（无成员行）。editor/owner 闸门仍要求真实成员。
- 问答链路（`routes/chat.py` / agent）：
  - `_assert_member_spaces`（scope 合法性）：scope ⊆ 成员空间 ∪ 可检索公共空间；
  - `_resolve_chat_scope`（生效集合）：候选 = 成员 ∪ 可检索公共空间，再与会话 scope 求交（空 scope = 全部候选）；
  - 引用富集 `enrich_hits` 对无成员关系的空间默认按 **viewer** 处理——公共空间命中仅可见"已过审"资产，天然复用先审后见语义。
- API Key / OAuth 令牌身份不涉及公共空间（无用户分组）。

## 五、API 契约（OpenAPI 已导出，sdk-ts 已再生）

### 运营域 `/api/v1/ops/*`（`routes/ops/`，域级 `ops_audit` 兜底审计，object_type=ops_request）

| 方法与路径 | 说明 |
|---|---|
| `GET /ops/spaces` | 公共空间列表（含 member_count / group_count / 用量） |
| `POST /ops/spaces` | 创建公共空间（类型固定 public，创建者成为 owner） |
| `GET|PATCH|DELETE /ops/spaces/{space_id}` | 详情 / 设置（名称/描述/审核开关/配额）/ 删除（级联清理） |
| `GET /ops/spaces/{space_id}/usage` | 用量与配额 |
| `GET /ops/spaces/{space_id}/visibility` | 全部分组 + 当前空间勾选状态（可见性页签数据源） |
| `PUT /ops/spaces/{space_id}/visibility` | 全量替换勾选集合（body `group_ids`；显式审计 before/after） |
| `GET /ops/spaces/{space_id}/groups/{group_id}/members` | 只读：某分组成员（展开查看） |
| `GET|POST /ops/groups`、`PATCH|DELETE /ops/groups/{group_id}` | 分组 CRUD（重名 409；删除级联清勾选） |
| `GET|POST /ops/groups/{group_id}/members`、`DELETE .../members/{user_id}` | 分组成员管理（按用户名添加；重复 409） |

**闸门**：`require_ops(scope)` = 平台角色（operator/super_admin，auditor 拒绝）+ admin:read/admin:write scope（deps.py）。

**运营者成员兜底**：公共空间的内容管理复用用户域接口（上传/审核/图谱走 `require_space` 成员闸门），因此运营域内对具体空间的访问会自动把当前运营者补齐/提升为该空间 **owner 成员**（`ensure_owner_membership`，动作记审计 `ops.membership_granted/escalated`）。多运营者协作时互不阻塞。

### 用户域 `/api/v1/public-spaces`（`routes/public_spaces.py`）

| 方法与路径 | 说明 |
|---|---|
| `GET /public-spaces` | 当前用户经分组可见的公共空间（含 `linked` 状态） |
| `PUT /public-spaces/{space_id}/link` | 链接/断开（body `{linked: bool}`，幂等）；未对分组公开 → 403，空间不存在/非公共/已封禁 → 404 |

## 六、运营端前端（apps/ops）

- **骨架**：与 admin 同构（React 18 + Vite + Tailwind v4 + shadcn/ui、HashRouter、`createApiClient` + 401 处理 + `unwrap`），端口 **5175**（web 5173 / admin 5174），dev 入口 `pnpm dev:ops` / `make ops`，镜像 `apps/ops/Dockerfile`，Helm `templates/ops.yaml` + values `ops:` 段 + ingress `/ops` 路径。
- **角色闸**：`RequireOpsRole`（me.roles 含 operator/super_admin，否则 AccessDenied）；dev 登录默认签发 `operator`。
- **信息架构**：

```
/overview                总览：公共空间卡片 + 创建向导（名称/描述/先审后见）
/s/:spaceId              空间管理（页签布局，参照用户端 SpaceLayout）
  /assets                资产：Finder 式管理（目录树三视图 + 右键操作 + 拖拽/上传 + 筛选）；
                         双击资产在容器上层全幅覆盖查看（原始文件/MinerU 结果/chunk 管理）
  /review                审核：待审队列 + 通过/驳回（先审后见空间）
  /graph                 图谱：统计/实体检索/合并与回滚/重建
  /visibility            可见性：勾选用户分组（原「成员」语义的运营端形态）
  /settings              设置：基本信息/配额/危险区（删除空间）
/groups                  用户分组：分组卡片 CRUD + 成员管理（按用户名增删）
```

- **侧边栏**：固定导航（总览/用户分组）+ **公共空间动态列表**（点击进入对应空间管理界面，`['ops-spaces']` 缓存失效即时刷新）。
- **共享代码纪律**：上传管线提升至 `@loomvec/ui/lib/upload`（web 的 `@/upload` 改为再导出）；`ReviewStatusTag` 提升至 `@loomvec/ui/components/review-status-tag`；Finder 组件族（`@loomvec/ui/components/finder`：三视图容器 + 右键/拖拽/剪贴板 + 查看覆盖层 + `useFinder*` 数据 hooks）与 web 共用——运营端查看覆盖层开启 chunk 管理面板。运营端页面（资产/审核/图谱）参照 web 实现但**不做内容消费**（无检索/预览跳转/通知/对话）。

## 七、用户端改动（apps/web）

1. **空间管理页**：「公共空间」区——经分组可见的空间卡片（「公共」徽标）；**可点击进入**只读浏览（`/s/:id/assets`，虚拟 viewer）；卡片内链接开关仅控制问答检索源（`hooks`：`usePublicSpaces` / `useSpaceLinkToggle` / `useSpace`）。
2. **问答页**：召回空间选择器选项 = 我的空间 ∪ **已链接公共空间**（label 带「（公共）」后缀）；scope 持久化在会话 `scope_space_ids`，后端合法性校验与生效集合见 §四。
3. **空间内检索/图谱**：与本地 viewer 同权（只读）；聚合检索（顶栏「检索」）仍 = 成员空间，公共空间不进入。

## 八、决策记录（2026-09-14）

| 决策 | 理由 |
|---|---|
| 复用平台角色 operator/super_admin 作为运营角色，不新增角色 | 运营是内容运营子集；避免角色爆炸。auditor（全局只读审计）不进入运营域 |
| 公共空间走 `space_type=public` 而非独立布尔/新表 | 空间即知识源的单一模型不变；管理端空间治理/审核/管线自动覆盖公共空间 |
| 可见性 = 分组勾选行（无"全员"隐含语义，空 = 不公开） | 授权显式化，避免误公开；要全员则勾选覆盖全部成员的分组 |
| 用户链接与分组可见性双行存证、查询时求交（不级联清理链接） | 与"被移出成员即失权"的即时语义一致；避免批量清理的一致性负担 |
| 公共空间可见即可只读浏览；链接仅控制问答检索源 | 列表 = 可浏览目录；链接 = 是否纳入问答。与「先看再决定是否用于检索」的产品直觉一致；写路径仍锁真实成员 |
| 运营者访问公共空间自动获得 owner 成员行 | 内容管理链路复用用户域接口（单一授权路径），多运营者协作免手动转 owner |
| 上传管线/审核徽标提升到 `packages/ui` 单源 | 遵循前端规范"跨 app 共享禁止复制" |
