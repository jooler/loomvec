# LoomVec 开发计划总览

> 状态：v0.1（迭代中） · [00-项目核心文档](./00-项目核心文档.md) 的开发指导附件

## 一、阶段总览

| 阶段 | 文档 | 目标 | 预估量级 |
|---|---|---|---|
| **P0 工程骨架** | [07-阶段P0-工程骨架.md](./07-阶段P0-工程骨架.md) | 可开发的空转系统：monorepo、基础设施栈、CI、健康检查 | 小 |
| **P1 摄取与检索闭环** | [08-阶段P1-摄取与检索闭环.md](./08-阶段P1-摄取与检索闭环.md) | 跑通"上传→解析→LLM分片→嵌入→混合检索→回溯"核心闭环（单默认空间，文档/文本类） | 中 |
| **P2 空间协作与用户端** | [09-阶段P2-空间协作与用户端.md](./09-阶段P2-空间协作与用户端.md) | 多租户落地：空间/成员/角色/配额/审核流，用户端完整上传协作体验，图片管线 | 中 |
| **P3 图谱与问答** | [10-阶段P3-图谱与问答.md](./10-阶段P3-图谱与问答.md) | 图谱管线与三路混合召回、RAG 问答带引用定位、视频/音频管线 | 大 |
| **P4 运营端与企业化** | [11-阶段P4-运营端与企业化.md](./11-阶段P4-运营端与企业化.md) | 运维端全功能、OIDC SSO、OAuth 应用、Webhook、监控告警、K8s、发布合规 | 大 |

排序原则：
1. **关键路径优先**：检索闭环是产品灵魂，最先打通；空间模型 P0/P1 就以表结构与默认空间形式存在，P2 只是把用户界面和协作语义补上，避免返工；
2. **图谱放 P3 不放 P1**：图谱价值依赖足够的语料与稳定的分片质量，先让 L1/L2 检索站稳，再加 L3 扩展，且 P1 的 chunk_markers 契约为合并抽取预留了返回结构；
3. **重前端体验后置**：P1 用户端只做最小搜索页用于验证；完整 UX 在 P2/P3 随能力铺开；
4. **企业化收口**：SSO/OAuth/审计/监控在核心能力稳定后实施，避免底层返工带来的集成浪费。

## 二、工作流与任务编号

任务按工作流划分，编号 `P{n}-{工作流}-{序号}`：

| 工作流 | 代码 | 范围 |
|---|---|---|
| 基础设施/DevOps | INF | monorepo、compose/k8s、CI/CD、可观测性 |
| 核心领域库 | CORE | `services/core`：领域模型、管线定义、检索、授权 |
| 管线执行器 | WRK | `services/worker`：解析/分片/抽取/嵌入/索引任务 |
| API 服务 | API | `services/api`：路由、认证、契约 |
| 用户前端 | WEB | `apps/web` |
| 运维前端 | ADM | `apps/admin` |
| 质量 | QA | 测试、评测、验收 |

## 三、工程约定（全程生效）

1. **分支与提交**：main 受保护；功能分支 `feat/P{n}-{slug}`；提交信息 `[{P{n}-{task}}] 描述`；阶段任务分支合并需 CI 绿 + 自测清单勾完。
2. **契约先行**：API 变更先改 OpenAPI（代码内注解即源），`sdk-ts` 同步再生成后才动前端；破坏性变更禁止（当前仅 v1）。
3. **测试策略**：core/worker 单元测试 + PG/Milvus/RustFS 用 testcontainers 集成测试；API 契约测试（schema 快照）；前端 vitest 组件测试；每阶段交付跑 `evals/` 评测回归（P1 起建立金标集）。
4. **完成定义（DoD）**：代码合并 + 测试通过 + 契约文档更新 + 本地 compose 一键起全栈可演示 + 审计点（如涉写操作）落实。
5. **AI 调用规范**：一切经 core `ai/` 网关（OpenAI 兼容），禁止业务代码直连供应商 SDK；密钥只经环境变量注入；测试一律 mock 网关。
6. **数据模型纪律**：`tenant_id` / `space_id` / `created_at` / `updated_at` 自 P0 起存在于所有业务表；迁移只增不删，Alembic 串行演进；迁移 seed 值与代码常量的对应关系以注释互指（迁移文件保持独立可执行）。
7. **标识与配置纪律**（P1 起）：跨服务字符串标识（队列名 / Redis 键 / 事件类型 / scope）一律单源于 `core/constants.py`，禁止字面量散落；可运维参数（超时 / 上限 / 批量 / 窗口）一律进 `Settings` 并同步 `.env.example`，代码内常量仅限纯算法细节。
8. **API 分层**：路由薄壳（参数解析+序列化）→ `api/services/`（业务逻辑）→ `core/db/repos.py`（数据访问）；跨路由复用与核心域（资产等）的契约模型集中 `api/schemas/`，路由本地的简单请求/响应模型可内联在路由文件——类名即 OpenAPI component 名，移动不改名即不破坏契约。空间等请求级语义经 `deps.py` 依赖注入，不在路由内硬编码。

## 四、阶段通用退出标准

每阶段退出前核对：
- [ ] 本阶段任务全部 DoD 达成；
- [ ] compose 全栈一键起，冒烟脚本（`scripts/smoke/`）通过；
- [ ] `evals/` 评测回归通过（P1 起）；
- [ ] 新增配置项均有 `.env.example` 与文档同步；
- [ ] 阶段演示走查（按 04/05 文档的角色场景抽查）无阻断问题。

## 五、跨阶段风险提示

- **云端 AI 配额/限流**：P1 起压测批处理吞吐，尽早确认供应商配额与账单量级；
- **MinerU 部署体积与模型下载**：P0 就验证 compose 内 MinerU 可用（含模型缓存卷），避免 P1 阻塞；
- **AGE 扩展镜像**：PG18 + AGE 需自构建或选社区镜像，P0 验证；
- **Milvus 稀疏向量/ BM25 Function 行为**：P1 用小样本验证分词与召回质量，不达预期及时调整方案（备选：应用层分词 + sparse 输入）。
