# LoomVec 技术方案与架构设计

> 定位：企业级数字资产管理（DAM）+ 多模态语义检索平台。
> 一句话：**用 DAM 的严谨管理资产，用多模态向量让资产"可被语义找到"，命中后精确回溯到页码 / 图片区域 / 视频时间点。**

## 一、总体架构

```
┌─────────────────────────────────────────────────────────────────────┐
│  接入层                                                              │
│  Web 用户端 (React SPA)   运营管理端 (React SPA)   开放 API (REST)    │
│        │                      │                       │              │
│        └────────────── API Gateway / FastAPI ────────────────┐      │
│           鉴权(JWT/OIDC) · API Key · 限流 · 审计 · 租户隔离    │      │
└──────────────────────────────────────────────────────────────┼──────┘
                                                               │
┌──────────────────────────────┐    ┌───────────────────────────▼──────┐
│  核心服务 (FastAPI, async)    │    │  处理管线 (Celery + Redis)        │
│  · 资产/空间/权限服务          │───▶│  parse → chunk → embed → index   │
│  · 检索服务(混合召回+重排)     │    │  （图谱 enrich 随 P3 加入）        │
│  · 元数据/标签/分类服务        │    │  每步可重试、可观测、进度可见        │
└──────┬───────────┬───────────┘    └──────┬───────────┬───────────────┘
       │           │                       │           │
┌──────▼───┐ ┌───────────┐          ┌──────────┐ ┌──────────────────┐
│PostgreSQL│ │   Milvus  │          │  RustFS  │ │ AI 基础设施       │
│ 资产/语义  │ │ 稠密+稀疏  │          │ 原始文件+ │ │ 云端 API          │
│ 单元/用户/ │ │ 多向量字段 │          │ 派生物    │ │ (embed/VL/rank)  │
│ 审计/API  │ │ BM25 混合  │          │ (S3 兼容)│ │ 端点可配置，内网化 │
└──────────┘ └───────────┘          └──────────┘ │ 时改配置即可      │
                                                  └──────────────────┘
```

设计原则：
- **读写分离的索引模型**：PostgreSQL 是唯一事实源（资产、语义单元、权限），Milvus 只存向量与最简过滤字段，可随时全量重建。
- **管线即产品**：每个资产的摄取管线是一个可观测的任务 DAG，运营端能看到每个文件卡在哪一步、失败原因、一键重试。
- **检索层接口化**：初始即采用 Milvus（Standalone 起步，K8s 分布式演进），`Retriever` 抽象保留用于防锁定与检索效果评测对比。
- **模型无关**：所有 AI 调用统一走 OpenAI 兼容端点；**向量化、rerank、VLM、LLM 直接使用云服务，平台不内置模型服务**；服务地址、密钥、模型名均为配置项，未来内网化时改为自托管端点（Infinity/vLLM）即可；嵌入模型可配置、支持全量重嵌入。

## 二、技术栈清单

| 层 | 选型 | 理由 |
|---|---|---|
| **后端** | Python 3.12 + FastAPI + Pydantic v2 + SQLAlchemy 2 + Alembic | 文档解析/AI 生态全在 Python；FastAPI 自动生成 OpenAPI 文档，正好支撑"API 优先" |
| **任务队列** | Celery + Redis（broker/result） | 视频转码、OCR、嵌入都是重任务；成熟的重试/优先级/死信/监控生态 |
| **前端** | TypeScript + React 18 + Vite + Tailwind CSS v4 + shadcn/ui + TanStack Query + react-router 7 + sonner + i18next/react-i18next | 组件代码进仓库完全自持、样式即 Tailwind 工具类；pnpm monorepo：`apps/web`（用户端）+ `apps/admin`（运营端，同构栈）；UI 文案经 i18next（当前仅 zh-CN，结构与类型多语言就绪，见决策记录与 apps/FRONTEND_CONVENTIONS.md §11） |
| **主数据库** | PostgreSQL 18（本机已安装 18.6；JSONB 存可配置元数据 + GIN 索引） | 事实源；元数据 schema 可配置且可过滤查询 |
| **向量库** | Milvus 2.6+（Standalone 模式起步） | 原生 BM25+dense 混合检索（RRF/WeightedRanker）、多向量字段同集合存储、Partition Key 租户隔离、Attu 管理界面；Apache-2.0 |
| **知识图谱** | PostgreSQL 扩展 Apache AGE（openCypher，支持 PG18） | 与事实源同库：事务一致、备份统一、运维零新增组件；实体链接向量存 Milvus `entities` 集合 |
| **对象存储** | RustFS（S3 完全兼容，Apache-2.0，Rust 实现） | MinIO 社区版归档后的主流替代；同时承担业务对象存储与 Milvus 的存储后端，生产可换云 S3/OSS |
| **缓存/队列** | Redis | broker + 缓存 + 限流计数 |
| **文本嵌入** | Qwen3-Embedding-0.6B（升级路径 4B）。**现网：百炼 text-embedding-v4（1024 维，支持 64~2048 自定义）** | Apache-2.0，中文强，32K 上下文，MRL 可裁剪维度 |
| **图文嵌入** | BGE-VL。**现网：百炼 multimodal-embedding-v1（1024 维，文/图同空间，DashScope 原生协议）** | MIT 可商用，MMEB SOTA，中文好 |
| **重排** | Qwen3-Reranker-0.6B 或 bge-reranker-v2-m3。**现网：百炼 qwen3-vl-rerank（DashScope 原生协议）** | 混合召回后 cross-encoder 精排 |
| **嵌入服务** | 云端 OpenAI 兼容 API（如阿里云百炼/DashScope 的 embedding、multimodal-embedding、rerank）；内网化时切换自托管 Infinity / vLLM | 向量化、rerank、VLM 调用全部经统一网关抽象，切换只改配置 |
| **文档解析** | MinerU（**内置自部署，主力**，License = Apache-2.0+附加条款，合规项见 03 文档）+ Apache Tika（MIME/兜底）+ PaddleOCR（复杂扫描件兜底） | 表格转 HTML、版面坐标、Markdown 输出供 LLM 分片；解析器接口抽象，可切换 Docling（MIT）。**实施注记（P1）**：MIME 嗅探以纯 Python 魔数校验落地（`core/pipeline/mime.py` 单点），Tika 与 PaddleOCR 兜底为后续替换项 |
| **图片处理** | pyvips（libvips）+ exiftool | 缩略图快、自动 EXIF 转向；提取 EXIF/IPTC/XMP 元数据 |
| **视频处理** | ffmpeg + PySceneDetect + faster-whisper（P3 规划，未实现） | 场景切分抽帧、元数据提取、音频转写 |
| **VLM/LLM** | 云端 VL/LLM API（qwen-vl 系等），用于 caption/图片理解、摘要/关键词；内网化时切换自托管 vLLM + Qwen2.5-VL | Apache-2.0；均为可选增强项，低配可关闭 |
| **鉴权** | 自建 RBAC（JWT）+ OIDC 对接企业 IdP（优先）+ OAuth 2.0 授权码流程 | 企业 SSO 与第三方用户级授权 |
| **部署** | Docker Compose（PG18 + Milvus Standalone + RustFS + Redis）→ K8s/Helm（Milvus 分布式） | 单机到集群平滑演进 |
| **可观测** | OpenTelemetry + Prometheus/Grafana + Loki | 管线监控是运营端核心需求 |

## 三、核心数据模型

> **实施注记（P2/P4）**：本节已按落地形态修订（迁移 0001~0004；源码
> `services/core/src/loomvec/core/db/models.py`）。与最初设计稿的主要差异：
> 处理状态与审核状态分列、标签为租户级、元数据内嵌资产行（无独立 asset_metadata 表）、
> 向量检索走 Milvus（设计稿中 Qdrant 为笔误）、locator 为回溯定位字段。

```sql
-- 租户与空间（多租户：tenant 为第一级隔离边界）
tenant(id, name, plan, status, quota_storage_bytes, quota_file_count)
space(id, tenant_id, slug, name, description, space_type[shared|personal],
      owner_id, review_required, embedding_model, chunk_preset,
      quota_storage_bytes, quota_file_count)     -- 一个空间=一个知识源，用户可自建
space_member(id, space_id, user_id, role[owner|editor|viewer], invited_by)  -- 资源级授权的落点

-- 资产（DAM 核心，借鉴 Pimcore/Nuxeo）
asset(id, tenant_id, space_id, folder_id,      -- folder_id 挂靠目录树（空 = 空间根目录）
      name, mime_type, ext, size_bytes, checksum, storage_key,
      status[pending|processing|ready|failed],          -- 管线处理状态
      status_reason,
      review_status[pending_review|approved|rejected]|NULL,  -- 先审后见（NULL=审核不适用）
      review_reason, reviewed_by, reviewed_at,
      created_by, user_meta JSONB,      -- 空间 schema 元数据（GIN 可过滤）
      category_id,                      -- 树形分类（空间内）
      asset_meta JSONB)                 -- 解析填充的元信息（页数/caption/宽高等）
asset_folder(id, tenant_id, space_id, parent_id, name, created_by)  -- Finder 目录树（迁移 0009；同父活文件夹名唯一，移动防环由服务层保证）
asset_version(id, asset_id, version, checksum, storage_key, inline_text,
              chunk_cache_key, version_meta JSONB)   -- 版本（P2 每次登记 v1）
asset_rendition(id, asset_id, version_id, kind[thumbnail|preview], storage_key,
                mime_type, width, height, size_bytes)  -- 派生物：缩略图随管线生成；预览转码懒生成
category(id, tenant_id, space_id, parent_id, name)               -- 树形分类
tag(id, tenant_id, name, created_by)  /  asset_tag(asset_id, tag_id)  -- 标签租户级共享，空间内使用
metadata_field(id, space_id, key, name, field_type[text|number|date|select],
               required, options JSONB)             -- 可配置元数据 schema（值落 asset.user_meta）

-- 语义单元（可被检索命中的最小语义粒度）
semantic_unit(
  id, tenant_id, asset_id, version_id, space_id,
  unit_type[text|table|image],     -- P2 落地三类；image_frame/transcript/caption/summary 为 P3+ 远期
  title, content,                  -- 文本内容 / caption + EXIF 摘要
  keywords JSONB,
  locator JSONB,                   -- 回溯定位：{pages, bbox, start_line, end_line}（视频帧/时间戳 P3 扩展）
  parent_id,                       -- 父子块（首片为父块）
  chunk_method[llm_markers|structural_fallback], order_index, char_count,
  embed_model_version)             -- 嵌入模型版本（重嵌入过渡期过滤 + 幂等跳过）

-- 平台运营与协作
processing_job(id, asset_id, version_id, job_type, status, progress, attempts, error, job_meta)
user / role / user_role / api_key(id, tenant_id, scopes, rate_limit_per_min, expires_at)
notification(id, tenant_id, user_id, type, title, payload JSONB, read_at)  -- P2 用户通知
space_usage(space_id, tenant_id, storage_bytes, file_count)                -- 配额计量
audit_log(id, tenant_id, actor_user_id, action, object_type, object_id, reason,
          before_value JSONB, after_value JSONB, request_id, ip)           -- P4 审计
-- P4 企业化（迁移 0004）
tenant_oidc_binding(id, tenant_id, domain, issuer, client_id, secret, enabled)  -- OIDC 域绑定
system_config(key, group, value JSONB, sensitive, ...)                     -- 动态配置（admin_settings 注册表）
oauth_client / oauth_authorization_code / oauth_access_token               -- OAuth 应用与用户级令牌
webhook_subscription(id, tenant_id, url, event_types, secret, paused)  /
webhook_delivery(id, subscription_id, event_type, status, attempt, response_status, next_retry_at)  -- Webhook（P4 已落地）
reembed_task(id, space_id, target_model, status, total/done/failed_assets) -- 重嵌入任务
entity / merge_log                                                          -- P3（未建）
```

**Milvus 集合设计**（`semantic_units`，一个 semantic_unit = 一行；实现见
`core/retrieval/store.py`）：
- 主键 `id`：即 PostgreSQL 中 semantic_unit 的 ID，Milvus 只做索引不做事实源
- `text_dense` FLOAT_VECTOR：文本嵌入向量（文档文本、表格、转写、caption、摘要都走此通道）
- `sparse_bm25` SPARSE_FLOAT_VECTOR：Milvus 内置 BM25 Function 自动生成（2.6 内置 jieba 分词器，无需应用层分词）
- `clip_dense` FLOAT_VECTOR：图文向量（图片行有值；**其余行补零向量**——Milvus 多向量字段无空值语义）
- 标量字段：`space_id`、`tenant_id`、`asset_id`、`unit_type`、`model_version`
  （租户/权限过滤经 expr；标签/分类等业务过滤先在 PG 收敛 asset_ids 再注入 expr；
  `space_id` Partition Key 为数据量增长后的优化项，P2 以标量 expr 过滤实现）
- 索引：稠密字段 HNSW（IP）、稀疏字段 SPARSE_INVERTED_INDEX
- 另设 `entities` 集合（P3）：实体名/描述向量 + 类型/社区标量字段，供查询期实体链接与图谱路径召回

检索时（实现见 `core/retrieval/retriever.py`）：查询文本 → 文本路 Milvus Hybrid Search
（text_dense + sparse_bm25 两路 RRF）与图片路 clip_dense 单路召回**并行执行后按分数合并**
（clip 通道未配置时自动降级为纯文本检索）→ 租户 × 空间（成员可见空间集）标量过滤 →
rerank 精排 → 服务层 PG 回表补全资产/空间信息并做审核可见性兜底。

## 四、摄取管线（按资产类型）

| 类型 | 管线 |
|---|---|
| Office/PDF/文本 | Tika MIME 侦测 → MinerU 解析（Markdown+表格 HTML+版面坐标）→ LLM 分片（chunk_markers；实体关系抽取与两阶段图谱合并随 P3 加入）→ 嵌入 + BM25 → 入库 |
| 扫描件/图片型 PDF | MinerU 内置 OCR（PP-OCR 系），复杂情况 PaddleOCR 兜底（后续；可选 ColQwen 视觉检索通道） |
| 图片 | **实施注记（P2）**：exiftool 元数据提取（可选，缺失降级）→ 缩略图 webp（pyvips 优先、Pillow 兜底，自动 EXIF 转向）→ 图文向量走 clip_dense 通道（`core/pipeline/image_flow.py`）→ VLM caption（可选开关）+ EXIF 文本入检索单元（BM25 可命中） |
| 视频 | （P3 规划，未实现）ffprobe 元数据 → PySceneDetect 场景切分 → 每场景 1~3 代表帧 + 缩略图 → 帧走 BGE-VL → Qwen2.5-VL 生成场景 caption → 音频 faster-whisper 转写（带时间戳分块）→ 全部带 `{time_start, time_end}` 定位入库 |
| 音频 | （P3 规划，未实现）faster-whisper 转写 → 时间戳分块 → 文本通道 |
| 其它 | Tika 抽文本尽力而为，保证"任何资产至少可被文件名/元数据检索" |

每个语义单元都带 `source_locator`，这是"命中后回溯原始来源"的保证：文档跳到页码+高亮区域，视频跳到时间点+关键帧，图片跳到原图。

## 五、API 与集成设计

- **配置分层（来源唯一，不做跨层兜底）**：
  1. **环境变量 / `.env`（基础设施与运行环境）**：PG/Redis/Milvus/对象存储连接、运行环境（ENV）、日志、认证密钥（JWT）、限流、worker 运行参数、OTel、**服务端口**（`LOOMVEC_API_PORT/WEB_PORT/ADMIN_PORT/OPS_PORT`，部署时灵活调整；API 经 `python -m loomvec.api` 启动、前端 dev server 经 vite.config 读取）；
  2. **`config/loomvec.json`（应用运行参数，应用自管理）**：AI 供方五通道（地址/密钥/模型）、MinerU 地址与后端、检索参数、管线分片参数、上传白名单、图片处理、图谱、媒体、转写、问答；路径经 `LOOMVEC_APP_CONFIG` 指定，缺省 `<仓库根>/config/loomvec.json`，支持部分覆盖，模板 `config/loomvec.example.json`；
  3. **DB `system_config`（admin 动态配置）**：管理端集中管理的运营可调项（检索/上传/图谱开关/AI 供方/SSO），DB 有值即生效、未配置回落 AppConfig——应用参数不经环境变量配置。
- **开放 REST API**（`/api/v1/*`）：资产 CRUD、检索（`POST /search`；响应的图谱证据路径随 P3）、空间/标签/分类/成员管理、Finder 目录域（`GET/POST /spaces/{id}/folders` 目录树、`PATCH /folders/{id}` 重命名、`POST /folders/{id}/move|copy` 移动/递归复制、`DELETE /folders/{id}` 级联删除、`PATCH /assets/{id}/location` 移动资产、`POST /assets/{id}/copy` 复制资产；资产列表 `folder_id` 参数按目录过滤，`'root'` 哨兵取根目录）；FastAPI 自动生成 OpenAPI 文档与多语言 SDK 骨架。
- **API Key 体系**：独立于用户的 key，scopes 精确到权限点，限流、过期、用量统计——应用级（租户级）集成的基础。
- **OAuth 2.0 授权码流程**：第三方应用经用户授权后以用户身份调用（用户级令牌，权限不超过用户本人），与 API Key 互补。
- **上传直传**：`POST /uploads` 签发 RustFS 预签名 URL（大文件 multipart），`POST /assets` 登记并触发管线；入口执行 MIME 嗅探、类型/大小白名单与空间配额校验，大文件流量不经过 API 服务。
- **契约约定**：全局错误结构（code/message/details）、游标分页、写操作幂等键——REST、SDK 与 Webhook 共用。
- **Webhook**：`asset.ready` / `asset.failed` / `job.progress` 等事件推送，第三方无需轮询。
- **MCP Server**（后续）：让 LoomVec 成为 AI 助手的知识工具。
- **数据源连接器**（后续，对标 Onyx）：S3、网盘、Confluence 等定期同步 + ACL 映射。

## 六、运营管理端功能清单

1. **内容运营**：资产审核（入库前/后人工复核 chunk 质量，参考 RAGFlow chunk 可视化编辑）、共享空间"先审后见"审核队列、标签/分类治理、批量操作、图谱实体合并审核与社区重建触发（随 P3）。
2. **管线监控**：任务队列看板（排队/进行中/失败）、失败原因、单文件重试与批量重跑、各阶段耗时统计。
3. **索引与模型管理**：嵌入模型配置、切换后全量/增量重嵌入、索引重建、检索质量评测集（hit-rate/MRR 回归）。
4. **租户与配额**：租户→空间两级的存储量+文件数配额、用量报表、全量空间视图（含个人空间）。
5. **用户与权限**：RBAC、SSO 配置、API Key 与 OAuth 应用签发及审计。
6. **系统**：审计日志、Webhook 管理、存储用量、备份恢复状态。

## 八、风险与对策

| 风险 | 对策 |
|---|---|
| GPU 资源成本（嵌入/VLM/转写） | 嵌入 0.6B 模型 CPU 可跑；VLM caption 设为可关闭的增强项；视频按需抽帧控制调用量；预览转码懒生成（首次播放触发，产物缓存复用） |
| MinerU/Marker 类强解析器 license 风险 | 主力用 MIT 的 Docling + Apache 的 Tika/PaddleOCR，规避 GPL/NC |
| Milvus 运维复杂度（依赖 etcd/对象存储） | 开发与中小规模用 Standalone 模式（单容器）+ RustFS 承担对象存储；K8s 阶段再用 Milvus Operator 分布式 |
| AI 依赖云服务（成本/限流/数据合规） | 统一 OpenAI 兼容网关抽象，可随时切自托管端点；CI 与评测用小样本 + mock；敏感数据上云前评估合规 |
| 嵌入模型升级导致全库重嵌入 | checksum + 模型版本标记，支持增量与断点续跑 |
| 中文检索质量 | jieba 分词 BM25 + 中文嵌入 + rerank 三重保障；建立中文评测集持续回归 |
| MinerU 附加条款（合并月收入>2000 万美元需商业许可；对外在线服务需显著标识） | 列为发版合规检查项；无法接受时按解析器接口整体切换 Docling（MIT） |
| LLM 分片/图谱抽取成本 | 分片与抽取合并为单次调用（全文仅送一次）；按 checksum+prompt 版本缓存；社区摘要设为低优先级异步任务；抽取失败仅降级重试、不阻塞分片入库 |
