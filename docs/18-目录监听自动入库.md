# 目录监听自动入库

## 用途

worker 周期扫描本机的一个平铺目录（典型场景：外部脚本或网盘同步客户端持续往里放 PDF），把已经写完整的新文件上传到对象存储、登记为资产，并走与用户上传相同的解析管线。管线跑完后照常执行知识库自动归类，必要时新建 `pending` 知识库节点（见 [17-层级知识库与权限.md](./17-层级知识库与权限.md)）。

## 配置

配置在 `config/loomvec.json` 的 `ingest_watch` 段（应用参数，不经环境变量；定义见 `services/core/src/loomvec/core/config.py` 的 `IngestWatchSettings`）：

| 键 | 默认值 | 含义 |
|---|---|---|
| `dir` | `""` | 监听目录，建议写绝对路径；空字符串表示功能关闭 |
| `space_id` | `""` | 入库目标空间 id。`dir` 非空时必填；id 不合法或空间不存在时，每轮扫描只记告警 `ingest_watch_space_missing`，不处理任何文件 |
| `poll_interval_seconds` | `60` | 扫描周期（秒） |
| `stability_seconds` | `120` | 稳定判定时长（秒），见下文；应不小于 2 倍 `poll_interval_seconds`，否则实际只由「连续两轮不变」决定 |
| `extensions` | `[".pdf"]` | 后缀白名单，不区分大小写，可不带点 |

`dir` 和 `space_id` 的真实值只写在本机 `config/loomvec.json`（该文件不入库）；模板 `config/loomvec.example.json` 中两者留空。配置在 worker 进程启动时读取，修改后需重启 worker。修改 `space_id` 后，`done` 行和指向监听自己入库资产的 `duplicate` 行不会迁移或重新入库到新空间；其余 `duplicate` 行若指向的资产既不在新空间也不在同租户已发布的公共空间（如旧目标空间里人工上传的，或新空间属于其他租户），会被重开并按新空间重新判定（见下文「失败、变化与清理」）；之后新出现或发生变化的文件，按新空间做去重（见下文去重）；修改 `dir` 后旧目录的台账行保留不动。

## 调度

- beat 周期任务 `ingest.watch_scan`（`services/worker/src/loomvec/worker/celery_app.py` 的 `ingest-watch-scan` 条目），投递到默认 `pipeline` 队列，`expires` 为一个扫描周期（队列积压时过期丢弃，不堆积重复扫描）；只有 worker 带 `-B` 运行（或另起 celery beat）时才会被调度。
- `dir` 为空时任务直接返回 `{"status": "disabled"}`，不连接数据库。
- 扫描互斥：Redis 锁 `loomvec:ingest_watch:lock`（redis-py `Lock`，加锁、续期、释放都按 token 原子校验），TTL 为 `max(5 × poll_interval_seconds, 300)` 秒，每处理完一个文件续期一次；worker 被强杀时锁最多残留一个 TTL。拿不到锁的一轮直接返回 `locked`；续期失败（锁已过期被他人持有）时停止本轮剩余文件。
- 每轮返回摘要：`scanned`（白名单文件数）、`stable`（本轮判定稳定的文件数）及各结果计数（`ingested` / `duplicate` / `awaiting_inflight` / `error` / `changed` / `skipped` / `enqueue_failed` / `resumed` / `reopened`）。

## 扫描与台账

实现见 `services/worker/src/loomvec/worker/ingest_watch.py`。

- **只扫描一层**：用 `os.scandir` 列出 `dir` 本层条目，不进入子目录。监听目录可能位于 NFS 共享盘，实现上不做任何递归遍历。跳过：以 `.` 开头的隐藏文件（多为同步客户端的临时文件）、非普通文件、**软链接**（不跟随，告警 `ingest_watch_skip_symlink`，防止把目录外的文件带进来）、**非 UTF-8 文件名**（如 GBK 字节名，告警 `ingest_watch_skip_undecodable_name`，数据库与对象存储 key 都要求 UTF-8）。
- **台账表** `ingest_file`（`services/core/src/loomvec/core/db/models/ingest.py` 的 `IngestFile`），每个 `(watch_dir, file_path)` 一行：`file_size`、`file_mtime`、`checksum`（sha256）、`status`、`asset_id`（关联资产，可空；外键延迟到提交时校验）、`stable_since`（当前大小与修改时间首次被观察到的时间）、`last_checked_at`（最近一次在目录中见到该文件的时间，终态行最多每天刷新一次）、`error_message`。新表由 `make init-db` 创建。每个文件的台账写入在独立保存点中完成，单行写入失败只跳过该文件，不影响同轮其他文件。
- **状态**：`pending_stable`（等待稳定）→ `uploaded`（已登记资产、尚未入队）→ `done`（已入队管线）；目标空间或同租户已发布的公共空间已有可用的同内容资产时为 `duplicate`；登记前任一步失败为 `error`。
- **稳定判定**：首次发现的文件登记为 `pending_stable`，本轮不处理；之后每轮比对大小和修改时间，有变化就刷新 `stable_since`；至少连续两轮不变且距 `stable_since` 已满 `stability_seconds` 才处理。读取文件后再核对一次大小和修改时间，仍在写入时重置计时、下轮再看。
- **读取**：在线程中读整文件，以 `O_NOFOLLOW | O_NONBLOCK` 打开并核对是普通文件（列目录后被替换成软链接或特殊文件也会被拒）；读取、计算 sha256 和上传对象存储期间不持有数据库事务。后缀为 `.pdf` 的文件还要通过便宜的完整性检查：前 1024 字节内有 `%PDF-`，末尾 1024 字节内有 `%%EOF`，否则记 `error`（缺 `%%EOF` 多为同步尚未写完，文件写完、大小或修改时间变化后自动重新处理）。
- **去重**：目标空间或同租户已发布的公共空间已有**可用的**同内容资产时记 `duplicate`（`asset_id` 指向该资产，可以在公共空间），不上传、不入队、不跑管线；日志 `ingest_watch_file_duplicate` 带该资产的 `asset_id`、`space_id` 与 `cross_space`（是否在目标空间以外）。同内容指 sha256 相同，只由文件字节决定，与文件名、路径、修改时间无关。处理失败（`failed`）的副本不算可用：即便失败只是暂时的（之后被人重跑成功），监听也会照常入库一份，最多多出一份副本。只认大家都看得到的副本：资产须在目标空间，或在**已发布的**公共空间——`space_type = public` 且至少对一个未删除的用户分组可见（`space_group_visibility`，与用户端公共空间可见性同口径）；需审核（`review_required`）的非目标空间只认审核通过（`approved`）的资产，分组用户只看得到这些。他人协作空间、个人空间、未发布的公共空间里的副本，以及审核空间里未通过审核的副本都不算，同内容照常入库到目标空间（重新跑一遍管线）。可用指：与目标空间同租户（`tenant_id` 可空，空租户之间按同一租户判），资产未删除、状态不是 `failed`、审核状态不是 `rejected`，所属空间未删除且未封禁（删除空间不软删其资产行，查询同时判空间）；其他租户的资产不算。同内容的判定来源：管线已算出相同 sha256 的资产（包括人工上传的；按 `asset.checksum` 索引 `ix_asset_checksum` 精确查找）、本路径上次入库的资产、同一监听目录其他路径入库的资产（刚登记、管线尚未写入 checksum 的也能认出）；几处来源合在一条查询里，命中多个时目标空间优先，其次最早入库的。
- **等待在途资产**：`asset.checksum` 由管线 parse 步骤在 MinerU 解析完成后才写入，人工上传的同一文件在排队或解析期间按 sha256 查不到。因此稳定的文件在读取之前先检查：若目标空间或同租户已发布的公共空间存在大小相同、`checksum` 为空、状态为 `pending` / `processing` 的可用资产（本监听目录登记的除外，其 sha256 已在台账中），本轮不读不传（结果 `awaiting_inflight`，台账保持 `pending_stable`），下轮重新判定；等待期间不读文件，不给 NFS 增加读取。自文件稳定（`stable_since`）起最多等 1 小时，超时照常入库。
- **入库**：先按与用户直传相同的上传策略校验后缀和大小（`upload.allowed_extensions` / `upload.max_size_bytes`，含 admin 动态配置覆盖；`extensions` 中不在上传白名单内的后缀会记 `error`），再写对象存储 raw bucket（key 规则同直传：`raw/{space_id}/{随机串}/{文件名}`），然后调用 `register_file_asset`（含两级配额闸门）登记到目标空间根目录：资产 id 预先由数据库 `uuidv7()` 分配，台账 `uploaded` + `asset_id` 与资产行在同一事务提交。最后 `enqueue_pipeline` 入队并记 `done`。资产名为文件名（论文 PDF 之后可能被管线按 `pipeline.auto_rename_papers` 自动改名）。
- **补偿入队**：每轮扫描先处理 `uploaded` 行——对应资产仍存在且处于 `pending` 时重新入队，然后记 `done`（资产已在处理或已删除时直接记 `done`）。入队失败（如 broker 不可用）或进程在登记与入队之间退出时，都由下一轮补偿，不会重复登记资产。`uploaded` 期间文件发生变化不会触发重新登记，补偿完成后再按新的大小与修改时间判定。

## 系统身份与资产权限

- 登记使用的身份沿用 api 层「`user_id` 以 `apikey:` 开头即非用户主体」的约定（`apikey:ingest-watch`），资产 `created_by` 为空，租户取目标空间的租户。
- 资产在 `asset_meta.source` 记来源标记 `ingest_watch`（`loomvec.core.constants.ASSET_SOURCE_INGEST_WATCH`）。带此标记且无上传人的资产，管理权限（编辑、自动改名、删除、移动、重跑管线、分片管理）按 `loomvec.core.authz.can_manage_asset` 的系统入库规则：空间 owner 与人类 editor 可管理，租户级 API Key 身份不可管理（不落入「API Key 登记的无主资产」那一类），viewer 不可。复制出的副本归复制者所有，不带来源标记，按普通上传判定。

## 失败、变化与清理

- 单个文件任何一步失败只把该行记为 `error` 并写入 `error_message`，本轮继续处理其他文件；资产登记失败时删除已上传的原始对象。已登记资产之后的失败不改为 `error`，保持 `uploaded` 等补偿。
- `error` 行在文件大小或修改时间变化后（例如修正原因后 `touch` 该文件）重新处理；文件不变则不重试。
- 已是 `done` / `duplicate` 的文件大小或修改时间变化后重新判定：内容未变且目标空间或已发布的公共空间仍有可用的同内容资产（优先原资产）时记 `duplicate`；否则作为新资产入库，原资产保留。
- `duplicate` 行指向的资产变得不可用（被删除、所在空间被删除或封禁、处理失败、审核驳回、所在公共空间撤销发布或审核未通过，或因修改 `space_id` 既不在目标空间也不在已发布的公共空间）时，每轮扫描开始把这些行改回 `pending_stable` 重新判定（结果计数 `reopened`）：目标空间或已发布的公共空间仍有其他可用的同内容资产则再记 `duplicate`，否则正常入库。监听自己入库的资产（`asset_meta.source` 为 `ingest_watch`）被人删除或变得不可用视为有意处理，不重开：`done` 行不重开，指向这类资产的 `duplicate` 行（同目录里的副本文件，或 `done` 行因修改时间变化重判后）也不重开，文件不变就不再入库。
- 从监听目录删除文件不影响已入库资产。台账行在文件从目录消失超过 7 天后删除（`uploaded` 行等补偿完成后再删）。
