# 16 - 本地模型推理

> 目标：在有 NVIDIA GPU 的宿主机上本地运行文本生成、向量、重排、图文（CLIP）四类模型，
> 使 `ai.llm / ai.embedding / ai.rerank / ai.clip` 四通道完全离线可用。VLM（图片/视频
> caption）未本地化，走云端供方或关闭。选型沿 `docs/01` 调研结论：嵌入/重排服务化首选
> Infinity（一进程多模型），LLM 用 vLLM。

## 一、组件与端口

统一由 `scripts/start-models-gpu.sh`（`start | stop | status | logs`）管理，
与 `scripts/start-mineru-gpu.sh` 同模式：独立 venv、权重预下载、只监听 127.0.0.1。

| 服务 | 端口（env 覆盖） | 模型 | 网关通道 | 协议 |
|---|---|---|---|---|
| vLLM | 38010（`MODELS_LLM_PORT`） | Qwen2.5-1.5B-Instruct-AWQ（别名 `qwen2.5-1.5b`、`deepseek-chat`） | `ai.llm` | OpenAI 兼容 `/v1/chat/completions`（JSON 模式、SSE 流式、工具调用） |
| Infinity | 38011（`MODELS_INFINITY_PORT`） | bge-m3（别名 `bge-m3`） | `ai.embedding` | OpenAI 式 `/embeddings` |
| ↑ 同进程 | ↑ | bge-reranker-v2-m3（别名 `bge-reranker-v2-m3`） | `ai.rerank` | Cohere/Jina 式 `/rerank`（`api_style: "openai"`） |
| ↑ 同进程 | ↑ | jina-clip-v2（别名 `jina-clip-v2`） | `ai.clip` | Infinity 协议（`api_style: "infinity"`，见下） |

默认档位为 1.5B AWQ（非思考型 instruct），给 16GB 卡上与 Infinity 三模型、MinerU 的共存
留显存（向量/重排优先占显存）。换档位：`export MODELS_LLM_ID=<HF repo>`（如
`Qwen/Qwen3-4B-Instruct-2507-FP8`）后 `stop && start`，并按权重大小调 `MODELS_VLLM_GPU_UTIL`；
档位约束：Qwen3 ≤1.7B 为混合思考模型，输出 `<think>` 会烧掉 `max_tokens` 并污染 JSON 输出，
不可选。模型带两个 serving 别名——`deepseek-chat` 使 agent/dsh 经 `ai.llm.base_url` 注入
`DEEPSEEK_BASE_URL` 后不改任何配置即可直连本地。

**`api_style: "infinity"`**（clip 通道专用，`AiGateway._clip_request_infinity`）：
Infinity 0.0.77 的多模态 `/embeddings` 不支持 Jina 混合 dict input，而是文本与图片分次
请求（字符串数组 + 顶层 `modality`；图片要 `data:image/jpeg;base64,` 前缀）。gateway 的
`clip_embed_texts` / `clip_embed_images` 各自整批转发，caption 仅 dashscope 通道使用。
嵌入/重排通道不受影响（OpenAI 兼容）。

## 二、首次安装与启动

两个独立 venv（避免 torch 版本互相牵制；共约 20GB 磁盘，权重另约 13GB）：

```bash
uv venv .venv-vllm     --python 3.12 && uv pip install --python .venv-vllm/bin/python vllm
uv venv .venv-infinity --python 3.12 && uv pip install --python .venv-infinity/bin/python \
  "infinity-emb[server,torch]" modelscope "typer>=0.16.1" einops timm torchvision aiohttp
```

依赖注记（均为实测踩坑，2026-09）：

- `typer>=0.16.1` 必须显式加：infinity-emb 0.0.77 声明的旧 typer 与 click>=8.3 冲突，
  启动报 `Secondary flag is not valid for non-boolean flag`；
- `einops / timm / torchvision / aiohttp` 是 jina-clip-v2 远程代码与图片输入的 import
  依赖（缺哪个报哪个的 ImportError / 500）；
- vLLM 侧无需系统 nvcc：脚本已设 `VLLM_USE_FLASHINFER_SAMPLER=0`（无 nvcc 时
  flashinfer 采样器 JIT 编译失败）并关 `--kernel-config enable_flashinfer_autotune`；
  装 CUDA toolkit（如 cuda-toolkit-13-4）后可开启，属可选加速项。

```bash
./scripts/start-models-gpu.sh start    # 首次自动下载权重（断点续传）；两服务就绪才返回
./scripts/start-models-gpu.sh status   # 两服务健康 + 显存占用
./scripts/start-models-gpu.sh logs     # tail 两个日志（tmp/dev-vllm.log / tmp/dev-infinity.log）
./scripts/start-models-gpu.sh stop
```

模型权重经 HuggingFace 下载到 `tmp/models/<名字>/`（`.download-ok` 哨兵防重复下载）。
网络实测注意（2026-09，脚本已内置处置）：

- `HF_HUB_DISABLE_XET=1` 必需：Xet CDN（us.aws.cdn.hf.co）在部分网络不可达；
- **不要安装 `hf_transfer`**：多并发下载会中途报错；
- `HF_ENDPOINT` 默认 `https://hf-mirror.com`（直连 huggingface.co 同期实测不稳定；
  MinerU 脚本默认 modelscope 是同一取舍）；
- `hf` 在仓库不可达时会"成功"返回本地目录并退出 0——脚本对四个权重目录做了落盘校验
  （`require_weights`），下载中断重跑 `start` 即可断点续传。

**jina-clip-v2 的依赖链**（其文本塔权重不在自己的 safetensors 里）：加载时嵌套拉取
`jinaai/jina-embeddings-v3`（文本塔权重，约 1.1GB fp16）与两个远程代码仓
`jinaai/jina-clip-implementation`、`jinaai/xlm-roberta-flash-implementation`。脚本把这
三个仓预取进 HF 缓存（`~/.cache/huggingface`），之后以 `HF_HUB_OFFLINE=1` 完全离线加载。
Infinity 启动另需 `INFINITY_BETTERTRANSFORMER=false`（optimum 未装时 infinity 0.0.77
的守卫有缺陷，报 `NameError: BetterTransformerManager`）。

## 三、应用接线

接线有三条等价路径：运维端「设置 → AI 供方」分层表单逐通道选「本地 GPU 推理」（实时探测
vLLM/Infinity 运行状态与 served 模型，不可用时禁选本地，一键写下方端点与协议）；
`./deploy.sh` 里逐通道选择（连同 MinerU 路线一起落配置）；或手工把模板
`config/loomvec.local-models.example.json` 的 `ai` 段合并进
`config/loomvec.json`（支持部分覆盖）。要点：

- `ai.mock=false`；`ai.llm/embedding/rerank` 指向 38010/38011 且 `api_style: "openai"`；
  `ai.clip` 指向 38011 且 `api_style: "infinity"`；
- `./dev.sh start` 按同一份配置派生要拉起的本地服务：`ai.*.base_url` 指向本地推理端口
  （127.0.0.1 的 `MODELS_LLM_PORT` / `MODELS_INFINITY_PORT`）的通道自动后台拉起
  `scripts/start-models-gpu.sh` 并只加载所选通道（`MODELS_LOAD_LLM / EMBEDDING / RERANK /
  CLIP`），改回云端地址即不再拉起，启动时无需重复选择；
- 改完须重启 api / worker / agent（`AiGateway` 启动时快照配置，`./dev.sh stop && ./dev.sh start`）；
- agent/dsh 的 `agent.model.max_tokens` 建议 ≤4096（本地 `max-model-len=16384`，dsh
  提示词+工具约 4.1K token；默认 8192 会 `CONTEXT_WINDOW_EXCEEDED`）；
- `ai.vlm` 未本地化：离线环境把 `image.caption_enabled` 置 `false`
  （同时门控图片 caption 与视频场景 caption），否则图片/视频摄取在 caption 步骤失败；
- admin 设置（DB `system_config`）的 `ai.*` 键有非空值时**优先于** `config/loomvec.json`：
  api/worker 网关在启动时合并（设置页标注「需重启」），agent/dsh 的
  `ai.llm.base_url / ai.llm.api_key` 则每会话即时读取——DB 种子里若是占位值
  （如「初始配置」）必须清掉，否则带假凭据请求报 `INVALID_CREDENTIAL`。

## 四、存量数据

切换嵌入模型后，存量空间的向量仍是旧模型产物（维度相同但语义空间不同）：

- 新空间创建时 `embedding_model` 选 `bge-m3`（`constants.EMBEDDING_MODELS` 白名单已含）；
- 存量空间走 admin 重嵌入（`pipeline.reembed_space`，目标模型选 `bge-m3`）；
- CLIP 向量不随文本重嵌入流程刷新：换 clip 模型后需重跑图片/视频资产（或重建空间）。

## 五、显存预算（16GB RTX A4000，ECC 开启实测）

| 占用 | 实测 |
|---|---|
| 桌面环境（浏览器等） | ~0.4GB |
| MinerU（稳态常驻；解析高峰另需 2~3GB） | ~1.1GB |
| Infinity（bge-m3 + bge-reranker-v2-m3 + jina-clip-v2 及其文本塔，fp16） | ~6.2GB |
| vLLM（`--gpu-memory-utilization 0.22`：AWQ 权重 1.6GB + 激活 + KV） | ~3.1GB |
| Whisper base（转写时懒加载） | ~0.7GB |

常驻合计约 11GB，留 ~2.7GB 给解析高峰；大 PDF 解析与转写并发时接近满卡，必要时错峰。
`nvidia-smi -e 0` 关 ECC 可再释放约 0.45GB（A4000 16GB 标称与可见量的差值；需 root +
重启生效，代价是放弃显存纠错，开发/推理场景常见取舍）。vLLM 参数随档位联动：
`MODELS_VLLM_GPU_UTIL`（默认 0.22）/ `MODELS_VLLM_MAX_MODEL_LEN`（默认 16384，
1.5B KV ≈ 0.9GB）。

## 六、运维边界

- 可手动管理（`start | stop | status | logs`），也可交由 `./dev.sh start` 按配置自动拉起
  （见 §三）；由 dev.sh 拉起的随 `./dev.sh stop` 一并停止（以 tmp/dev-models.started 标记
  区分），手动 start 的不受 dev.sh stop 影响；
- 通道选择性加载：`MODELS_LOAD_LLM / MODELS_LOAD_EMBEDDING / MODELS_LOAD_RERANK /
  MODELS_LOAD_CLIP`（`0` 跳过该通道的权重下载与启动；手动运行缺省全载，dev.sh 按配置注入）；
- 端口改动经 `MODELS_LLM_PORT` / `MODELS_INFINITY_PORT`，需同步改 `config/loomvec.json`；
- 对话模型回云供方：`ai.llm.base_url` / `api_key` 改回云端即可，`deepseek-chat`
  别名让 agent/dsh 无感切换；本地两服务可停。
