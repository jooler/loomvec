# P2 空间协作与用户端

> 上级：[06-开发计划总览](./06-开发计划总览.md) · 目标：**多租户与协作语义落地**——终端用户自建空间、邀请协作、上传编辑资产，检索/权限按"租户×空间×角色"三重过滤；图片管线接入；配额与审核流可用；用户端成为可日常使用的产品面。

## 一、范围

**做**：tenant/space/space_member 完整语义、两层权限落地（资源级授权进入查询与检索过滤）、配额硬校验、先审后见审核流、标签/分类/元数据、图片管线（缩略图/EXIF/图文向量）、个人中心与通知、用户端空间管理与资产编辑 UI。
**不做**：图谱、问答、视频/音频管线、OIDC 对接（仍 dev 登录 + 种子用户）、运维端业务页面（P4）。

## 二、任务分解

### CORE 核心领域库

| # | 任务 | 要点 |
|---|---|---|
| P2-CORE-01 | 空间与成员域 | space（type/owner/review_required/embedding_model/chunk_preset）、space_member（owner/editor/viewer）、成员变更事件；被移除即失权语义 |
| P2-CORE-02 | 资源级授权 | 授权服务：成员关系×审核状态判定；**注入所有仓储查询与 Retriever 过滤**（租户×空间×角色）；P1 默认空间迁移到该模型 |
| P2-CORE-03 | 配额服务 | 存储量+文件数计量（space_usage）、租户→空间两级切分、上传闸门、用量查询 |
| P2-CORE-04 | 标签/分类/元数据 | tag/category（树形）/metadata_field+JSONB 存储；空间 schema 校验；元数据过滤进入检索 |
| P2-CORE-05 | 图片处理服务 | pyvips 缩略图（EXIF 转向）、exiftool 元数据提取、BGE-VL 图文向量（clip_dense 通道）、VLM caption（可选开关） |

> **嵌入选型与维度说明（2026-09-12 实测定论）**：`text-embedding-v4` 默认 1024 维、
> 支持 64~2048 自定义（经 `AI__EMBEDDING__DIMENSIONS` 透传，网关已实现）；
> `multimodal-embedding-v1` 固定 1024 维；`tongyi-embedding-vision-flash/plus` 实测
> 768/1152 维（不支持自定义到 2048+，百炼全线无 2560 维模型）。双通道维度解耦：
> Milvus `text_dense` 与 `clip_dense` 是独立向量场、各自建 HNSW 索引，维度可以不同。
> 保持"文本嵌入 + 多模态嵌入"双通道而非统一多模态：文档检索是主场景，
> text-embedding-v4 对纯文本判别力优于多模态模型（后者为跨模态对齐牺牲文本精度）；
> 两者 top-1 判别力横评（本仓库 3 图 3 查询）均 3/3，multimodal-embedding-v1 余弦
> 间隔更大，维持现选型。若未来要统一为单模型，仅需将两通道指向同一模型/维度并重建
> 集合，代码零改动。
>
